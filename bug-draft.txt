Subject: Wildcard URL forward ignores its destination and redirects to http with the path dropped (loganfinney.com)

Hello,

The wildcard URL forward on my domain loganfinney.com doesn't follow its settings.

Current forwards:

| Host | Destination | Type | Include path | Wildcard |
|---|---|---|---|---|
| *.loganfinney.com | https://loganfinney.com | permanent | yes | yes |
| blog.loganfinney.com | https://thegemstone.org | permanent | yes | no |

Expected: https://anything.loganfinney.com/page → 301 https://loganfinney.com/page

Actual: https://anything.loganfinney.com/page → 301 http://loganfinney.com

The wildcard forward switches to http and drops the path. Every server behind uixie.porkbun.com (207.207.210.23, .36 and .50) does this, for both http and https requests.

What I tested:
1. The named blog forward works correctly. https://blog.loganfinney.com/x → 301 https://thegemstone.org/x
2. A temporary named forward also worked. It was test.loganfinney.com → https://loganfinney.com, permanent, include path on, wildcard off. https://test.loganfinney.com/x → 301 https://loganfinney.com/x. So the same destination works in a named forward.
3. The wildcard forward ignores its destination. I set it to three different destinations in turn:
   - https://loganfinney.com
   - https://www.loganfinney.com
   - https://www.example.com
   Each time, the wildcard still redirected to http://loganfinney.com with the path dropped.
4. The certificate is fine. The forwarder serves a valid Let's Encrypt certificate for *.loganfinney.com, issued Oct 13, 2026. The problem is only the redirect target.

To reproduce:

curl -sI https://randomname.loganfinney.com/x   # Location: http://loganfinney.com
curl -sI https://blog.loganfinney.com/x         # Location: https://thegemstone.org/x

Please make the wildcard forward use its configured destination and https, and keep the path when "include path" is on.

Thank you,
Logan Finney
